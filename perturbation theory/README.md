# Mandelbrot · Perturbation theory

Самостоятельный эксперимент на WPF / .NET 10 в подготовленной заготовке. Основная версия FractalExplorerWPF остаётся отдельным приложением.

## Запуск

Из корня репозитория:

```powershell
dotnet build '.\perturbation theory\perturbation theory\perturbation theory.slnx' -c Release
dotnet run --project '.\perturbation theory\perturbation theory\perturbation theory\perturbation theory.csproj' -c Release
```

## Окно

Упрощённое окно `Views/MandelbrotWindow` основной WPF-версии: та же компоновка, базовые стили, девять встроенных палитр, плавная и дискретная окраска. Формула — только классическое множество Мандельброта `z² + c`.

- Колесо мыши приближает точку под курсором; левая кнопка перемещает изображение.
- Последний кадр сразу трансформируется при навигации; новый постепенно накладывается поверх него. Расчёт начинается через 180 мс после последнего изменения.
- Кнопка `✕` скрывает панель, `☰` возвращает её. F11 переключает полный экран.
- Esc отменяет расчёт; в полном экране сначала возвращает обычное окно. Enter запускает рендер.
- Можно менять число итераций, радиус выхода, число потоков, центр и зум. Числа принимают точку, запятую и запись вида `1e18`.
- «Пример глубокого зума» открывает участок с увеличением `1e12` и 4000 итераций.
- Статистика показывает время кадра, время и длину опорной орбиты, число переустановок базы и пикселей, потребовавших прямого пересчёта.

Редакторы палитр, сохранения, экспорт, визуализация сетки и остальные способы окрашивания не перенесены. Настройки живут только в текущем окне.

## Что считает движок

Одна опорная орбита на кадр:

```text
Z[0] = 0
Z[m+1] = Z[m]² + C
```

Для каждого пикселя вычисляются только отклонения:

```text
δz[0] = 0
δz[n+1] = 2·Z[m]·δz[n] + δz[n]² + δc
z_pixel = Z[m] + δz[n]
```

`δc` формируется из экранного смещения до преобразования в `double`: маленькое смещение не прибавляется к большому double-центру. Координаты и навигация хранятся в `decimal`.

Индексы пикселя `n` и опорной орбиты `m` независимы. Когда `|Z[m] + δz| < |δz|` или опорная орбита закончилась, выполняется rebasing: `δz = z_pixel`, `m = 0`. Счётчик итераций пикселя продолжает расти. Поэтому выход центра за порог не обрывает расчёт остальных точек.

При особенно сильном вычитании близких величин пиксель пересчитывается прямым методом выбранной точности. Это защитный путь, его использование явно отражается в статистике. Аналитически внутренние точки кардиоиды, круга периода два и действительного отрезка `[-2; 0.25]` пропускаются.

Формула perturbation и правило rebasing: [Claude Heiland-Allen, Deep Zoom](https://mathr.co.uk/web/deep-zoom.html). Линейные приближения и пропуск серий итераций здесь не реализованы: эксперимент проверяет сам переход к отклонениям.

## Режимы точности

| Режим | Опорная орбита | Отклонения | Назначение |
|---|---|---|---|
| `double → double` | double | double | Контрольный быстрый режим с ограниченной точностью опорной орбиты |
| `decimal → double` | decimal | double | Режим по умолчанию: точная опорная орбита и быстрый расчёт пикселей |
| `decimal → decimal` | decimal | decimal | Эксперимент полностью на decimal; больше арифметических операций на пиксель |

В последнем режиме отклонение хранится в масштабированном виде `δz = s·d`, где `s = 1e-12`:

```text
d' = 2·Z·d + s·d² + δc/s
```

Это существенно: обычный `decimal` округляет результаты до шага не меньше `1e-28`. Без масштабирования он быстро теряет разряды маленьких отклонений. В квадратичном члене сначала вычисляется `s·d`, чтобы не переполнить квадрат большой масштабированной величины. Логарифмы для окраски и диагностическое отношение величин вычисляются в double; сама итерация этого режима остаётся decimal.

`decimal` не является произвольной точностью. Опорная орбита и координаты ограничены его 28–29 значащими цифрами. UI допускает зум до `1e24`, но останавливает рендер при шаге пикселя меньше `1e-27` или слиянии соседних координат. Это ограничение представления, а не гарантия точности до `1e24`: чувствительность длинных орбит может испортить результат раньше. Численно проверены выборки до `1e18`.

## Проверка

Без сторонних тестовых пакетов, отдельным консольным проектом:

```powershell
dotnet run --project '.\perturbation theory\Verification\Verification.csproj' -c Release
dotnet run --project '.\perturbation theory\Verification\Verification.csproj' -c Release -- --benchmark
```

Проверяются:

- 1271 точка общего вида и 391 точка с быстро убегающей опорной орбитой, во всех трёх режимах;
- 77 точек при зуме `1e12` и 63 точки при `1e18`, в обоих decimal-режимах;
- независимый прямой эталон на 192-битной фиксированной арифметике `BigInteger`; точное совпадение числа итераций и признака выхода, допуски на плавное значение 0.002 и 0.02 для глубоких выборок;
- выход на последней разрешённой итерации, защитный пересчёт при сильном вычитании, отмена, пределы параметров, крайние тайлы, альфа-канал и одинаковый результат при разном числе потоков.

Пробный замер 02.09.2026: Release, 4 логических CPU, 128×80, зум `1e12`, 4000 итераций. Один проход, без статистического усреднения; результаты зависят от участка и загрузки компьютера:

| Расчёт | Время |
|---|---:|
| Perturbation `double → double` | 320 мс |
| Perturbation `decimal → double` | 244 мс |
| Perturbation `decimal → decimal`, масштабированные отклонения | 12 963 мс |
| Прямой decimal, даже без окрашивания | 3600 мс |

В этом замере все perturbation-режимы обошлись без аварийного прямого пересчёта. Гибрид был примерно в 15 раз быстрее прямого decimal, а полностью decimal — примерно в 3.6 раза медленнее. Perturbation сама по себе не сокращает число итераций; выигрыш гибрида даёт перенос основной работы в double.

## Файлы

- `MainWindow.xaml`, `.xaml.cs` — единственное окно, навигация, фоновые сессии и показ тайлов.
- `Models/` — параметры и фиксированные RGB-палитры.
- `Core/Rendering/PerturbationRenderer.cs` — опорные орбиты, отклонения, rebasing, защитный пересчёт и параллельный рендер.
- `Core/Rendering/PaletteSampler.cs` — два способа окраски, адаптированные из основного WPF-движка.
- `Infrastructure/RenderSurfaceMetrics.cs` — перенесённое измерение полотна с учётом DPI.
- `Theming/ThemeStyles.xaml` — необходимое подмножество стилей основной WPF-версии.
- `Verification/` — независимая численная проверка и воспроизводимый замер скорости.
